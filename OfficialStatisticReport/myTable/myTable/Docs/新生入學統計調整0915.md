# 新生入學統計調整紀錄（2025/09/15）

## 1. 修改檔案

- `Form2.cs`
  - `LoadConfigXml()`：改寫載入流程
  - 調整 `BindConfigMappingsToGrid()`：依預設標記清單建列；Config 有有效 `source` 時優先使用；Config 無 target 或 `source` 為空／空白時，若來源清單有完全同名項目則自動填入

## 2. 原始問題

### 2.1 預設標記列數不足（已修正）

開啟「新生入學統計」表單時，三個 DataGridView 的列數由 Config 內已儲存的 `<item>` 數量決定。

若 Config 已存在但只含部分預設標記，畫面上就只會顯示那些已儲存項目，其餘預設選項會消失。

例：`dataGridViewX1` 應有 11 種入學方式，但 Config 只存 3 筆時，畫面上只剩 3 列。

### 2.2 Config 無對應時來源不自動同名填入（已修正）

Config 沒有某標記的對應時，來源欄一律留空，即使來源清單（學生類別 Tag）已有與標記文字完全相同的項目，也不會自動帶入，使用者需手動選取。

### 2.3 Config 有 target 但 source 空白時仍不自動同名填入（本次修正）

Config 已有該 `target`，但 `source=""`（或僅空白字元）時，舊邏輯因 `mappings.ContainsKey(target)` 為 true，直接採用空白 source，不會再檢查來源清單是否有完全同名項目。

例：

```xml
<item
    target="入學身份:外加錄取--原住民生"
    source="" />
```

即使來源清單已有 `入學身份:外加錄取--原住民生`，UI 仍顯示空白。

## 3. 根本原因

舊版 `LoadConfigXml()` 在 Config 區段存在時，直接以 Config 的 `item` 迴圈新增列：

- Config 有幾筆 → UI 顯示幾列
- 預設標記清單（`Column2.Items` 等）只在「該區段完全不存在」時才用來補列

另外，初次建立空白 Config 時雖有建立 `<入學方式>` 節點與其 11 個 item，但未執行 `config.AppendChild(EnterSchool_Way)`，導致初始 Config 可能缺少「入學方式」區段。

來源載入方面，先前邏輯為：

```text
Config 有 target → 用 Config source（含空白）
Config 無 target → 再檢查同名來源
```

因此「有 target 但 source 空白」被當成已設定，無法觸發同名自動填入。

## 4. `LoadConfigXml()` 變更內容

新流程：

1. 先清除三個 DataGridView 既有列（避免重載重複）。
2. 若 Config 為 `null`，建立空白設定檔（含三個區段），並補上 `config.AppendChild(EnterSchool_Way)`。
3. 一律以預設標記清單建立列。
4. 讀取對應 Config 區段，組成 `Dictionary<target, source>`。
5. 以精確 `target` 比對填入 `source`；僅在 Config source 有效時採用；否則再以來源清單同名比對（見第 7 節）。

Config **不再**決定要顯示幾個標記列。

## 5. 預設標記列數

## 6. Config `target` → `source` 對應行為

每個區段（`<入學方式>` / `<入學身分>` / `<新生中具原住民身分者>`）內的 `<item>`：

- 以 `target` 屬性作為字典鍵
- 以 `source` 屬性作為對應值
- 載入時對預設標記做精確字串比對
- **僅非空白的 Config source 為最高優先**，不會因來源清單有同名項目而被覆寫
- 若 Config 無此 `target`，或 `source` 為空／空白，則改嘗試同名來源自動填入

## 7. 來源載入優先順序（本次更新）

`BindConfigMappingsToGrid()` 同時接收來源 ComboBox 項目集合，並以 `HashSet`（`StringComparer.Ordinal`）做**完全相等**比對。

優先順序：

```text
1. Config 含此 target，且 source 非空／非空白
   → 使用 Config source

2. Config 無此 target，或 Config source 為空／空白，
   且來源清單有與 target 完全相同文字的項目
   → 自動填入該同名來源

3. 以上皆非
   → source 留空 ""
```

決策程式片段：

```csharp
if (mappings.ContainsKey(target) &&
    !string.IsNullOrWhiteSpace(mappings[target]))
{
    source = mappings[target];
}
else if (sourceSet.Contains(target))
{
    source = target;
}
```

規則：

- 僅使用精確字串比對（`Ordinal`）
- 不做部分比對、模糊比對、開頭／結尾比對、大小寫忽略比對
- `dataGridViewX1` / `X2` / `X3` 三個 Grid 共用同一 `BindConfigMappingsToGrid()` 邏輯
- 來源清單對應：`Column3` / `dataGridViewComboBoxExColumn2` / `dataGridViewComboBoxExColumn4`（皆由 `Column3Prepare()` 以顯示文字填入）

既有**有效** Config 對應不會被清空或覆寫。

## 8. DataGridView 列清除行為

`LoadConfigXml()` 開頭執行：

```csharp
dataGridViewX1.Rows.Clear();
dataGridViewX2.Rows.Clear();
dataGridViewX3.Rows.Clear();
```

重設／重載再次呼叫 `LoadConfigXml()` 時不會產生重複列。

## 9. 初始 Config「入學方式」節點修正

`config == null` 分支建立空白設定檔時，於寫入 11 個入學方式 item 後新增：

```csharp
config.AppendChild(EnterSchool_Way);
```

初始 Config 結構為：

```xml
<新生入學統計報表_來源目標設定Config>
    <入學方式>...</入學方式>
    <入學身分>...</入學身分>
    <新生中具原住民身分者>...</新生中具原住民身分者>
</新生入學統計報表_來源目標設定Config>
```

Config key 維持不變：`新生入學統計報表_來源目標設定Config`。
